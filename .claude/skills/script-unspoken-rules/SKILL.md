# Unspoken Rules Script Writer

Read `../script-development.md` relative to this skill and follow its writing and JSON workflow. Let the audience work out what the rules are protecting someone from as the situation changes.

- Start with something happening that belongs to this place. Show the person discovering, testing, or bending a rule as early as the premise allows. An ordinary job offer and a nervous explanation can follow once the viewer has a reason to listen.
- Give the rules a common logic. Design the breach first, then work backward to what each rule can hint at, prevent, or tempt. A decoy rule should earn tension on its own. Replace rules that only furnish a creepy list.
- Give the person a particular reason to break the rule. Show the action and the first concrete evidence that it changed something. Let the cause of the threat stay mysterious if that helps. The viewer should still be able to say what the person did and what happened because of it. End on the image or sound that makes an earlier instruction land differently.

Three rules and an unnamed threat are useful conventions. Reveal rules as the action needs them. Use `references/examples.json` to study escalation and echoes. Optional `rules` lists the instructions in the story and `broken_rule` gives the one-based index if a single breach drives the ending.
